# The model catalog, starter tiers and routing rules

The app never fetches the catalog at runtime: it is embedded at build time
(`qm_providers::catalog::Catalog::embedded`), so updates ship with a rebuild. A malformed file is
reported at startup as a `CatalogError`.

## Files

| File | What | Edit by hand? |
|---|---|---|
| `crates/qm-providers/catalog/snapshot.json` | every model our providers list, normalised | **No**: generated by `refresh.py` |
| `crates/qm-providers/catalog/refresh.py` | the generator; `PROVIDERS` maps models.dev ids to our wire names | yes |
| `crates/qm-providers/catalog/corrections.toml` | what models.dev lacks or gets wrong | yes |
| `crates/qm-providers/src/catalog/starter.rs` | legacy starter tier preset definitions | yes |
| `qm_types::domain::KindRow` | the task-kind rows and their default tiers (`default_tier`) | yes |

## Refreshing the snapshot

```sh
python3 -I crates/qm-providers/catalog/refresh.py                 # fetches https://models.dev/api.json
python3 -I crates/qm-providers/catalog/refresh.py --input api.json # or a saved copy
```

Standard library only. Review the diff like code: models gone, ids renamed, context windows
changed. Then remove corrections that name models the snapshot no longer lists, and check every
starter placement still names a real canonical id (swap a vanished one for the nearest real model
and tell the user).

## Corrections

`[providers.<wire name>]` sets defaults for a provider; `[[models]]` (`provider`, `id`) overrides
one model. Keys:

- `efforts`: the rungs of our ladder the model supports (`low`, `medium`, `high`, `xhigh`, `max`).
  It is a set, not a ceiling. Empty means no effort setting is sent.
- `effort_values`: the provider value each rung is sent as, when it isn't the rung's own name
  (`off` turns thinking off however the API does it).
- `compat`: adapter flags. Chat Completions: `CompatFlag` in
  `src/adapters/chat_completions.rs`. Responses: `supports_developer_role`,
  `supports_max_output_tokens`, `always_include_encrypted_reasoning`. Anthropic:
  `supports_eager_tool_input_streaming`, `supports_cache_control_on_tools`.
- `image_input`, `context_window`.

Leave a comment with the source (the provider's docs) for every non-obvious correction.

## Starter tiers

Placements name **canonical** model ids, so one model reached through two accounts shares one
placement. These are legacy preset definitions; account detection no longer seeds them. New
installs start with empty tiers, and existing saved placements are preserved. The explicit
`qm_core::routing::seed_starter_tiers` helper remains available, but is not called at startup or
when connecting an account. Only the Claude set is user-approved; other sets remain drafts.

## Routing rules

Task kind → tier is `qm_routing::rules`: `row_for` maps a kind and its checked `builds_on` fact
(never task text) to a `KindRow`, whose tier is the user's `[routing.kinds]` setting or
`KindRow::default_tier`. Change a default there, and in `docs/routing.md`'s table. Each tier's default effort lives
in `config.toml` (`[tiers]`, defaults in `qm_types::config::TierEfforts`).

## Verify

`cargo xtask check` and `cargo build` (the routing tests cover the defaults), then open Settings ▸
Model levels in a throwaway run (skill `run-by-hand`) and check the tiers and efforts shown.
